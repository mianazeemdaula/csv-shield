# CSV Shield

A CSV repair tool that runs in your browser. Files are read with the browser's File API and processed by the JavaScript on the page; they are not uploaded.

## What it does

- **Repairs unescaped quotes.** `2,"Bob "The Builder" Smith",...` or `24" Monitor` are rewritten with standard RFC 4180 quoting so rows stop shifting into the wrong columns. Valid files come back unchanged.
- **Fixes garbled characters (mojibake).** Text that was UTF-8 but got read as Windows-1252 (`CafÃ©`, `Itâ€™s`, `â‚¬`) is turned back into the original characters. Runs that do not decode as valid UTF-8 are left alone, so correct text such as `SÃO PAULO` is not touched.
- **Detects the delimiter** (comma, semicolon, tab, pipe).
- **Optional clean-up:** trim spaces, drop blank rows, pad short rows to the header's column count, remove exact duplicate rows (off by default, because identical rows can be real).
- **Optional masking:** emails (`a***@example.com`), phone-formatted numbers and card numbers (last four digits kept). Bare digit runs such as order numbers and ISBNs, and dates, are left alone. Masking is pattern matching: it does not find names, addresses or free-text mentions.
- **Export:** CSV (optionally with a UTF-8 BOM for Excel, optionally writing leading-zero codes as `="07030"` for Excel), JSON, Markdown, SQL `INSERT`.
- **Request list:** the "Check" button lists every request the browser has recorded for the page, live, using the Resource Timing API.

## Pages

- `index.html`: the full tool.
- Six topic pages (`fix-*.html`, `salesforce-*.html`, `offline-*.html`) and `seo-hub.html`, each with a short guide and a small version of the tool that uses the same engine. They are generated by `tools/build_landing_pages.py`; edit that file, not the HTML.

## Run it

Open `index.html` in a browser, or serve the folder (`python -m http.server 8000`) and open `http://localhost:8000`. The stress sample in the tool is loaded with `fetch`, so that one needs the local server.

## Tests

```
node tests/run_tests.js         # 50 checks from the original package
node tests/regression_tests.js  # 23 checks that valid data is left alone and repairs are right
```

Tested on 17 October 2026 with Node 22 and headless Chrome 155 (main page and all six topic pages). Not tested: Firefox, Safari, real phones, files over a few MB.

## Known limits

- Quote repair is a heuristic. Ambiguous cases, such as a quote right before a comma inside a field, may need a manual check; repaired cells are highlighted.
- Files are processed in one go on the main thread. Very large files (hundreds of MB) will be slow or may run out of memory.
- The field rules of any import target (required columns, date formats, picklists in Shopify, Salesforce or a database) are not checked.
